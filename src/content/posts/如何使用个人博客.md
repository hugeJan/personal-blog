这篇文章记录当前博客系统的完整使用规则。博客源码保存在 GitHub，Cloudflare Pages 负责构建和发布。

~~~text
本地文件 → GitHub main 分支 → Cloudflare Pages → 公开网站
~~~

当前项目：

- GitHub 仓库：[hugeJan/personal-blog](https://github.com/hugeJan/personal-blog)
- 公开网站：[https://personal-blog-9s3.pages.dev/](https://personal-blog-9s3.pages.dev/)
- 生产分支：<code>main</code>

## 1. 目录规则

| 内容 | 正确位置 | 说明 |
| --- | --- | --- |
| 博客文章 | <code>src/content/posts/</code> | 只在这里新建 <code>.md</code> 或 <code>.mdx</code> 文件 |
| About 页面内容 | <code>src/content/pages/about.md</code> | 修改 About 页正文 |
| 首页介绍 | <code>src/pages/index.astro</code> | 修改首页标题下方的介绍文字 |
| 归档页面程序 | <code>src/pages/archives/index.astro</code> | 自动读取文章，不需要为每篇文章手动修改 |
| 文章列表程序 | <code>src/pages/posts/[...page].astro</code> | 自动分页显示已发布文章 |
| 网站配置 | <code>astro-paper.config.ts</code> | 网站名称、链接、功能开关等 |
| 静态图片 | <code>public/images/</code> | 可在 Markdown 中通过 <code>/images/文件名</code> 引用 |

不要把文章放进 <code>src/pages/posts/</code>。这个目录存放页面路由程序，不是文章集合。

不要直接修改 <code>dist/</code>、<code>node_modules/</code> 或 <code>.astro/</code>。这些目录由构建工具生成或管理。

## 2. 新建一篇文章

在 <code>src/content/posts/</code> 新建文件，例如：

~~~text
src/content/posts/my-first-post.md
~~~

文件名会影响文章 URL。文件名可以使用中文，但使用小写英文和短横线更容易分享，例如 <code>my-first-post.md</code>。

文章必须包含 Frontmatter（文件头元数据）。最小可用模板如下：

~~~md
---
title: "我的第一篇文章"
pubDatetime: 2026-08-08T20:00:00+08:00
description: "文章简介。"
tags: []
draft: false
---

这里写正文。

## 小标题

正文支持 Markdown。
~~~

Frontmatter 的开始和结束标记必须单独占一行：<code>---</code>。

## 3. Frontmatter 字段规则

| 字段 | 类型 | 是否必需 | 作用 |
| --- | --- | --- | --- |
| <code>title</code> | 字符串 | 是 | 文章标题 |
| <code>pubDatetime</code> | 日期时间 | 是 | 发布时间，也决定 Archives 的年月分组 |
| <code>description</code> | 字符串 | 是 | 文章简介，用于列表和页面元信息 |
| <code>draft</code> | 布尔值 | 否 | <code>true</code> 时不发布；建议正式文章明确写 <code>false</code> |
| <code>featured</code> | 布尔值 | 否 | <code>true</code> 时显示在首页 Featured 区域 |
| <code>tags</code> | 字符串数组 | 否 | 文章标签；不需要标签时写 <code>[]</code> |
| <code>modDatetime</code> | 日期时间或 <code>null</code> | 否 | 修改文章时填写，用于显示更新时间 |
| <code>author</code> | 字符串 | 否 | 作者；不填写时使用站点默认作者 <code>hugeJan</code> |
| <code>ogImage</code> | 图片路径或 URL | 否 | 分享到社交平台时使用的预览图 |
| <code>canonicalURL</code> | URL 字符串 | 否 | 文章的规范 URL，通常不需要填写 |
| <code>hideEditPost</code> | 布尔值 | 否 | <code>true</code> 时隐藏文章页的编辑链接 |
| <code>timezone</code> | 字符串 | 否 | 单篇文章使用的时区，例如 <code>Asia/Shanghai</code> |

日期建议使用带时区的 ISO 格式：

~~~yaml
pubDatetime: 2026-08-08T20:00:00+08:00
~~~

### 草稿和定时发布

- <code>draft: true</code>：文章不会出现在生产环境的首页、Posts 或 Archives。
- <code>draft: false</code>：文章可以正常发布。
- <code>pubDatetime</code> 为未来时间时，生产环境会等到发布时间附近再显示。
- 本地开发环境会显示非草稿文章，便于提前预览定时文章。

正式发布前，确认 <code>draft: false</code>，并检查 <code>pubDatetime</code>。

## 4. Featured、Archives 和 Tags

### Featured（精选）

精选不是单独上传的页面。将文章 Frontmatter 设置为：

~~~yaml
featured: true
~~~

文章会从首页的 <code>Recent Posts</code> 移到 <code>Featured</code> 区域。没有任何文章设置 <code>featured: true</code> 时，首页不会显示精选区域。

首页最多显示配置中的数量；当前 <code>perIndex</code> 为 <code>4</code>。完整文章仍然可以在 Posts 页面访问。

### Archives（归档）

Archives 页面由 <code>src/pages/archives/index.astro</code> 自动生成，不需要手动创建文章卡片。

符合发布条件的文章会按照 <code>pubDatetime</code> 自动按年份和月份分组。访问地址：

- 本地：<code>http://localhost:4321/archives/</code>
- 线上：<code>https://personal-blog-9s3.pages.dev/archives/</code>

如果 Archives 为空，先检查文章是否放在 <code>src/content/posts/</code>，以及 <code>draft</code> 和 <code>pubDatetime</code> 是否正确。

### Tags（标签）

顶部导航中的 Tags 已移除。文章仍然支持 <code>tags</code> 字段，并可能在文章页底部显示标签。

不需要标签时，明确写：

~~~yaml
tags: []
~~~

## 5. Markdown 正文

文章正文支持常用 Markdown 语法：

~~~~md
## 二级标题

普通段落。

- 无序列表
- 另一项

1. 有序列表
2. 另一项

[链接文字](https://example.com)

~~~ts
const message = "代码块";
~~~
~~~~

### 插入图片

将图片放入：

~~~text
public/images/example.png
~~~

在文章中引用：

~~~md
![图片说明](/images/example.png)
~~~

图片路径区分大小写。文件名中建议使用英文、数字和短横线。

### 使用 MDX

需要在 Markdown 中使用 AstroPaper 支持的组件或交互内容时，可以使用 <code>.mdx</code> 扩展名。普通文章优先使用 <code>.md</code>，这样更简单，也更容易排查格式问题。

## 6. 本地预览

进入项目目录：

~~~bash
cd "/Users/huuymjan/Documents/ChatGPT/个人博客"
~~~

启动开发服务器：

~~~bash
npm run dev
~~~

常用本地地址：

- 首页：<code>http://localhost:4321/</code>
- 所有文章：<code>http://localhost:4321/posts/</code>
- About：<code>http://localhost:4321/about/</code>
- Archives：<code>http://localhost:4321/archives/</code>
- 搜索：<code>http://localhost:4321/search/</code>

文章 URL 通常是：

~~~text
http://localhost:4321/posts/文件名/
~~~

开发服务器运行时，保存 <code>.md</code> 文件后通常会自动刷新，不需要每次重启。如果页面没有变化，先刷新浏览器；仍然无变化时，再停止并重新运行 <code>npm run dev</code>。

## 7. 构建检查

推送到 GitHub 前，建议运行：

~~~bash
npm run build
~~~

这个命令会执行类型检查、Astro 构建、搜索索引生成和静态文件整理。出现错误时，不要继续发布；先修复终端中最早出现的错误。

文章数量变化后，如果本地搜索结果没有更新，重新运行 <code>npm run build</code>。

## 8. 发布到 GitHub 和 Cloudflare

确认本地页面正常后，查看变更：

~~~bash
git status
~~~

提交文章或配置修改：

~~~bash
git add .
git commit -m "feat: add or update blog content"
git push origin main
~~~

只想提交单篇文章时，可以使用：

~~~bash
git add "src/content/posts/文章文件名.md"
git commit -m "feat: add blog post"
git push origin main
~~~

Cloudflare Pages 当前使用以下设置：

- GitHub 仓库：<code>hugeJan/personal-blog</code>
- 生产分支：<code>main</code>
- 构建命令：<code>npm run build</code>
- 输出目录：<code>dist</code>
- 自动部署：已启用

推送到 <code>main</code> 后，Cloudflare 会自动构建。Cloudflare 控制台只用于查看部署状态，不需要手动上传 <code>dist</code>。

## 9. 修改站点其他内容

### 修改 About

编辑：

~~~text
src/content/pages/about.md
~~~

保留文件头中的 <code>title</code>。修改正文后，重新预览并提交。

### 修改首页介绍

编辑：

~~~text
src/pages/index.astro
~~~

首页的 <code>Featured</code> 和 <code>Recent Posts</code> 会根据文章 Frontmatter 自动生成，不需要手动复制文章标题。

### 修改站点名称、链接和功能

编辑：

~~~text
astro-paper.config.ts
~~~

当前常用配置包括：

- <code>site.title</code>：站点名称
- <code>site.description</code>：站点描述
- <code>site.url</code>：公开站点地址
- <code>socials</code>：首页和页脚的社交链接
- <code>features.showArchives</code>：是否显示 Archives
- <code>features.search</code>：是否启用搜索
- <code>posts.perPage</code>：Posts 每页文章数
- <code>posts.perIndex</code>：首页 Recent Posts 数量

修改配置后，必须重新运行 <code>npm run build</code> 检查。

## 10. 常见问题

### 文章不出现在 Posts

按以下顺序检查：

1. 文件是否位于 <code>src/content/posts/</code>。
2. 文件扩展名是否为 <code>.md</code> 或 <code>.mdx</code>。
3. Frontmatter 是否包含 <code>title</code>、<code>pubDatetime</code> 和 <code>description</code>。
4. <code>draft</code> 是否为 <code>false</code>。
5. <code>pubDatetime</code> 是否写成了未来时间。
6. 是否访问了正确的 <code>/posts/</code> 页面。

### 首页没有 Featured

确认文章 Frontmatter 中存在：

~~~yaml
featured: true
~~~

没有任何精选文章时，首页不会显示 <code>Featured</code> 标题。

### Archives 没有文章

Archives 不读取 <code>src/pages/archives/</code> 中的 Markdown 文件。它只读取 <code>src/content/posts/</code> 中符合发布条件的文章。

### 页面报 Missing content entry: about.md

确认以下文件存在：

~~~text
src/content/pages/about.md
~~~

不要删除这个文件；About 路由需要它。

### Cloudflare 线上没有更新

确认以下事项：

1. <code>git push origin main</code> 已成功执行。
2. GitHub 仓库中已经出现最新提交。
3. Cloudflare Pages 的 Deployments 页面显示构建成功。
4. 浏览器刷新了线上地址，而不是仍在查看 <code>localhost</code>。
